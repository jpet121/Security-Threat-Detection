# Editable rule configuration (schema version 1)

Copy `rules/default.toml` to a protected local file. The packaged copy and repository copy start byte-identical; editing the repository file requires `--rules` to select it. Every rule requires exactly: `id`, `version`, `classification`, `formats`, `fields`, `pattern`, `description`, `priority`, `enabled`. IDs must be unique ASCII identifiers up to 80 characters; patterns up to 8192 characters. Patterns use the pinned Python `regex` package. All patterns, including disabled rules, are compiled before evidence processing. The SHA-256 of the entire configuration binds every hit to its exact rules and thresholds.

Supported formats: `ssh`, `http`, `console`. Authentication rules can select `auth_message` or `event`, on SSH/console only. Injection rules can select only documented `request.*` fields. Enabling broad application event regexes can introduce false positives; operators own the meaning of their configured events. Priorities and descriptions are labels, not evidence of attack success.

Default injection signatures identify command substitution or a shell separator followed by `cat`, `id`, `whoami`, `curl`, `wget`, `bash`, `sh`, `nc`, or Python commands. Lone punctuation is insufficient. Inspection evaluates the recorded value and up to two strictly UTF-8 percent-decoded variants. It does not rewrite evidence, apply HTML decoding, interpret shell grammar or turn plus signs into form spaces. Malformed percent escapes/decode-depth bounds are review conditions. Form-encoded `+` spaces, uncommon commands, alternate encodings, escaped quotes and novel evasion syntax may evade these signatures; use original evidence and additional specialist analysis.

`[groups]` supplies positive count/window thresholds: `repeat_count`, `spray_accounts`, `burst_count`, `window_seconds`. These engineering defaults are not customer-certified incident thresholds. A group is a forward-looking inclusive window anchored on a known-time authentication event; repeat groups match that account, spray groups match that source IP, and cross-server bursts require at least two recorded servers. Proximity counts injection events within the configured interval on either side; it never asserts common actor or causality. Account/IP absence does not create a fabricated shared key. Unknown times do not enter windows.

`[limits]` documents per-line/event, field, normalization, operation-time, expansion and disk ceilings. Integers are required except operation/window seconds. All are positive finite values. Max event size is 16 MiB, decoded-field input 1 Mi characters, depth 5 and regex time 1 second. Configure lower values for untrusted collections. Multiple rules/fields multiply operation time; a timeout applies per regex call, not to the full audit.

Optional `[console]` patterns: `prefix` (strip one leading match), `boundary` (new record boundary), `timestamp` (must contain named group `timestamp`). Keep patterns anchored to documented layouts. Timestamp values must be parseable ISO datetimes. All custom pattern calls use the same operation timeout. Bad schema/syntax is rejected before scanning; semantically wrong patterns can still miss events and require labeled evaluation.
